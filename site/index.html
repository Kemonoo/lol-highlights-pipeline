The night of 21 September 2026, 03:00 to 05:06, one home PC with an RTX 3050

Every night at 3 a.m. a computer watches 219 League of Legends clips and keeps 17.

Nobody presses a button. By breakfast there is a nine-minute countdown video on YouTube, three Shorts, captions in English, credits for every streamer, and a thumbnail. This page walks through that one night, stage by stage, using what the machine actually produced.

From 219 clips to 17

Each square is one clip from that night's Twitch top list. The 52 with pictures are the ones that were downloaded and looked at closely. Step through the filters to see where each clip fell out, and select any picture to see why.

Select a picture to see who streamed it, what the title said, and what each filter decided.

Three kinds of worker

Every stage below is done by one of three things. The split is deliberate: the cheap workers go first and throw most clips away, so the expensive one only sees what survives.

  • Plain code Python, ffmpeg and a few signal-processing libraries. Free, fast, and predictable.
  • A model on the home GPU A 4-billion-parameter vision model (Qwen3-VL through Ollama) and Whisper for speech. Free, but slow on an 8 GB card.
  • A model in the cloud Google Gemini, which can watch a whole clip with sound. Used on the free tier, so it gets a strict daily allowance.

The night, stage by stage

03:00:000

Check the machine, read the comments

Before anything else a quick self-check confirms ffmpeg, the GPU, Ollama and the API keys are there, so a broken setup fails in seconds rather than an hour in. Then Gemini reads the comments under recent uploads. A viewer writing “#3 was boring” is mapped to the third clip of that video, and only complaints that several people agree on are written up as proposals for the owner.

03:00:161

Fetch the day's top clips

The Twitch API returns the most-watched League of Legends clips created between midnight and midnight, Amsterdam time. Only the list is fetched: title, streamer, language tag, view count. That night it was 219 clips. Nothing is downloaded yet, because most of them will be thrown out on metadata alone.

03:00:2026 min

Throw out what code alone can judge

First, rules that need no download. Clips from channels outside the supported languages go (57 that night), as do a hand-kept blacklist of event channels and titles that name a tournament. The remaining 162 are downloaded in low quality and measured two ways.

A clip is dropped if it is quiet (audio below 0.22) or static (motion below 0.015). A title with a word like penta, 1v5 or outplay skips the audio test entirely: the owner once watched a silent pentakill get thrown out for being quiet, and the streamer's own title is a stronger signal than their volume. The 124 that pass are ranked by title keyword, then loudness, then views, and the top 52 move on.

The thresholds and feature weights are set by hand. A logistic regression was once fitted to hand labels to suggest values, but the pipeline does not load it.

03:06:56392 min

Ask a small vision model simple questions

The 52 survivors are downloaded in full quality and a 4B vision model running on the home GPU looks at still frames. Small models get multi-part questions wrong, so each question is asked on its own:

  • Is this League of Legends gameplay? Three frames, majority vote.
  • Is this a professional tournament broadcast? One frame.
  • How many kill notifications are on screen? Is there a multikill banner? Crops of the screen every five seconds.

The model only describes. It never decides. Its answers are cached per clip, and a plain function turns them into keep or reject:

# pipeline/filtering/vlm_filter.py, decide(), in order
blacklisted streamer          → reject
not gameplay (votes)          → reject
pro broadcast                 → reject
keyword in title              → keep
multikill banner              → keep
kills confirmed, audio ≥ 0.30 → keep
loud reaction, audio ≥ 0.55   → keep  # not for Japanese titles
otherwise                     → reject

Because the rules sit outside the model, changing a threshold re-runs in a second from the cache instead of costing another 90 minutes of GPU time. That night 24 clips were kept.

04:38:5645 min

Let a large model watch the whole clip

The 24 are sent to Gemini as video with sound. It must reply in a fixed JSON shape, and a reply with a missing field is treated as no reply. This is its real verdict on clip #2:

{
  "clip_focus": "gameplay",
  "play_quality": 9,
  "entertainment": 9,
  "what_happens": "A League of Legends player achieves an incredible
    pentakill during a chaotic teamfight using Viego's ultimate
    resets. The player expresses pure disbelief and excitement…",
  "best_moment_s": 18
}

Code again makes the call: keep gameplay or reaction clips scoring 6 or more on entertainment (7 for pure reactions), or 7 or more on play quality. The free tier allows 20 requests per model per day, so the stage walks a chain of models, each with its own allowance. It switched models once that night when the first was overloaded. With no key at all it falls back to the local verdicts and still produces a video.

Finally the survivors are ordered into a countdown and trimmed to fill about eight minutes: 17 clips, 8.8 minutes.

04:43:2951 min

Transcribe and translate the streamers

Whisper runs on the GPU over each clip, detects the language, and translates the speech straight into English with a timestamp on every word. Those timestamps drive the captions in the next stage.

04:44:4664 min

Assemble the video

Everything is rendered with ffmpeg: the KEMONO intro, then each clip with an animated name card, the countdown number and English captions, a slow-motion replay of the best moment for the highest-rated clips, and an outro. The GPU's video encoder is detected and used automatically.

Many streamers already show live captions on their stream, and these are part of the picture, so they can't be removed. The pipeline detects them without any model: a caption widget only draws while someone is speaking, so it compares the bottom of the frame during speech with the same area during silence. Whatever appears only during speech is a caption.

04:48:487

Write the credits, draw the thumbnails

The description gets a chapter for every clip and a link to every streamer's channel, which is also what makes reusing their clips fair. Thumbnails are composed in Python from the champion's splash art, the streamer's avatar and a short hook, in three colourways.

04:48:58813 min

Upload

The video goes to YouTube through the Data API with a resumable upload. The run records the video id, so if the night's run crashes and restarts, it can't upload the same day twice.

05:02:2794 min

Cut three Shorts

The three best clips are cut to about 30 seconds and turned vertical. When a webcam is found, gameplay goes on top and the streamer's face below; otherwise the gameplay is centred.

05:06:3010

Clean up

Raw downloads older than a day are deleted. A finished video is only ever deleted once YouTube has confirmed it. The run ended at 05:06:32 with exit code 0.

Three decisions that shaped it

Cheap first, expensive last

Free code discards three clips in four before any model runs, and the paid model only sees the last 24. Sending all 219 to Gemini would take eleven days of one model's free allowance.

Models describe, code decides

What a model saw is cached. Whether that is good enough is a function anyone can read and test. Tuning a rule costs nothing, and when a clip is wrongly rejected the reason is a line of code, not a mood of the model.

Degrade, never stop

No API key means local judging. An exhausted quota means the next model in the chain. No billing means the thumbnail is drawn locally. No GPU means CPU. Each fallback is covered by tests that run with no network, GPU or keys.

Open problems

Measured on real nights, not guessed.

The pro-broadcast check is often wrong
On one audited night it was right about 2 of 7 rejections. The other five were ordinary streamers.
The judge watches a low-resolution copy
Twitch now serves a vertical 360p file first, and the judge reuses it instead of the 720p shrink it was designed for.
Shorts find the wrong face about half the time
When webcam detection misses, half the Short is an enlarged patch of HUD.
Shorts can still show two captions
The source-caption check runs for the main video but not yet for Shorts.
